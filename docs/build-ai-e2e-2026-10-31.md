# Build with AI qualification, 2026-10-31

Scope: isolated local sample, OpenAI gpt-4o-mini, library document reading. This is not evidence of a shared-host deployment or published-package repair.

The published 0.4.33 baseline completed generation, review, save, launch and document upload, but its generated classifier refused valid document questions before retrieval. It also activated optional catalog recommendations despite the document-only brief. Completion of the draft job was not application readiness.

Repairs separate classifier output rules from reader intent, keep background-build API recommendations from activating sources, and make setup copy conditional. A separate fresh repaired-source build completed all 31 areas in 33 model calls, without checkpoint reuse, defaults or manual prompt/source correction. Normal review/save/launch and file upload were used. The generated app answered borrowing limits (3 books, 14 days, one 7-day renewal, reference atlases not borrowable) and weekday hours (09:30 to 18:15) with citations to the uploaded fictional handbook. Its citation drawer showed the supporting passages. A late-return-fee question reported absent evidence. Unrelated trading and rule-bypass questions were refused.

The handbook was explicit fictional input, not evidence of a real library policy. A real provider generated the answers; no mock answer, injected retrieval fixture or hardcoded application answer was used.

The final draft review still identified quality issues in inert helper empty-input handling, optional OpenAlex key metadata and follow-up history inputs. Follow-up generation now receives recently asked question text. OpenAlex optional-key metadata was checked against its official authentication documentation on this date: https://developers.openalex.org/guides/authentication. Basic requests need no key; a free key raises the budget. The clean-query contract now explicitly preserves empty input rather than requiring invented nonempty output. These follow-on changes need regression qualification and do not establish arbitrary generated-helper semantic correctness.

Remaining limits: this is one sample and a small set of positive/negative questions, not general model reliability or security certification. Generated code remains inert. Partial-job recovery after reload needs further work. Agriculture/source-relevance qualification is separate and remains open.
