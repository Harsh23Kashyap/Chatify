# Publishing Chatify

Distribution: chatify-app. Executables: chatify and chatify-app. Bare invocation starts the local Demo. The PyPI name chatify belongs to another project; never use `pip install chatify` for this repository.

**Published:** https://pypi.org/project/chatify-app/. The standard local command is `uvx chatify-app`. Python/pip fallback after release: `python -m pip install chatify-app`, then `chatify-app`. Prefer uvx/pipx or a fresh virtual environment, not a shared system Python. Requires Python >=3.10. The core dependency has a tested major-version range (PyYAML>=6.0.3,<7). Optional PDF and semantic dependencies are not installed by default; model downloads never happen implicitly.

The manual pypi.yml workflow builds wheel/sdist, checks metadata, tests the same wheel on Linux/macOS/Windows and Python3.10/3.12, and only publishes when explicitly selected. It uses PyPI trusted publishing, no long-lived API token. For a new publishing account, register a pending publisher: project chatify-app, owner Harsh23Kashyap, repository chatify, workflow filename pypi.yml, environment pypi. That registration does not reserve the name. Use a GitHub environment approval gate for releases.

Current artifact acceptance covers isolated pip install/pip check, paths with spaces, packaged Demo documents, offline answers without optional extras, Python floor metadata, executable aliases, incompatible core-dependency diagnosis/repair, deleted dependency repair, and explicit isolation from host PYTHONPATH conflicts. It is not proof against every library/environment conflict. Ordinary shared-environment pip can change dependencies; reinstall in a private environment rather than repairing unrelated packages. `python -I` ignores PYTHONPATH/user-site pollution. Optional semantic models and OCR binaries need their own validation.

Existing installer scenarios also cover partial environment repair, repeat installs, interrupted receipt state, lock contention, occupied ports, health and configuration lock. Actual absent-uv bootstrap was previously checked on Linux only; The release workflow now also exercises the actual official bootstrap with uv removed from PATH and a disposable empty HOME on each OS. Linux passes locally; new macOS/Windows jobs must pass before claiming all-platform bootstrap verification. This is absent-uv testing, not proof on a machine with no Python, shell, curl or Windows networking tools. Offline first installs require cached dependencies; no network cannot conjure an absent package or Python runtime.

Before each release, verify account access, publisher settings, the exact release commit, build artifacts and the multi-OS acceptance jobs. Publication is complete only after PyPI serves the release and a clean registry install works. Local tests alone do not prove publication.
